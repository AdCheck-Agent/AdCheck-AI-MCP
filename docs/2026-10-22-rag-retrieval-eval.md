## 확인된 문제

### 1. 점수로 "관련 있음/없음"을 구분할 수 없다 — 파트 1 공유 필요

| 점수 | 평균 | 범위 |
|---|---:|---|
| 정답 근거 점수 | 0.50 | 최소 0.08 |
| 무관 문구의 1위 점수 | 0.42 | 0.36~0.50 |

운동화 할인·브런치 신메뉴처럼 무관한 문구에도 사회 근거 5개가 항상 반환되고,
1위 점수가 실제 정답 점수와 같은 범위에 있다. 따라서:

- `min_score`로 거르면 무관 문구보다 정답이 먼저 사라진다. 기본값 0.0은 유지했다.

| min_score | 결과가 남는 무관 문구 | 정답이 남는 문항 | 그중 기업 |
|---:|---:|---:|---:|
| 0.35 | 4/4 | 20/23 | 6/8 |
| 0.40 | 2/4 | 15/23 | 3/8 |
| 0.45 | 1/4 | 13/23 | 2/8 |

- **검색 결과가 있다는 것, 점수가 높다는 것을 근거 충분으로 해석하면 안 된다.**
  관련성 판단은 판정 단계(파트 1)에서 snippet을 읽고 해야 한다. 기존 문서의 원칙과 같다.

### 2. 일부 문서가 대부분의 질문에서 상위에 나온다

`RULE-HIST-001`, `RULE-CONTEXT-001`이 무관 문구 4개 모두에서 1~2위를 차지했고,
`SOC-02`, `SOC-05`, `SOC-12`에서도 정답보다 앞에 나왔다.
일반적인 서술이 많은 기준 문서가 어떤 질문과도 비슷하게 계산되는 것으로 보인다.

### 3. 기업 검색 점수가 전반적으로 낮다

기업 정답 점수는 0.08~0.65로 사회보다 낮다. 특히 `TGB-04`("실제 비건 인증을 받았는가")는
4위·0.08이다. 문서에 인증 정보가 없다는 것이 문항의 의도이므로 낮은 점수 자체는 문제가 아니지만,
사회와 기업 점수를 같은 기준으로 비교하면 안 된다.

## 추가 평가: 기업 방향성 행 추가 후

기업 문서의 목적은 광고가 **기업이 추구하는 방향과 어긋나는지** 보는 것이다.
그런데 기존 샘플은 금지 규칙뿐이었다. 그래서 두 기업의 `corporate_values`에 미션·핵심 가치·브랜드 톤·
주요 고객·약속 5행을 추가했다. 기업가치 문서는 3행 → 8행, 기업별 전체 근거는 9개 → 14개 chunk다.
구성은 [데이터 안내](../rag-mcp/data/README.md)에 정리했다. 광고 문구 형태의 방향성 불일치 질문 8개도 추가했다.
전체 결과: [retrieval-corporate-direction.json](eval/retrieval-corporate-direction.json)

| 기업 검색 (top_k=5) | 문항 | hit@1 | hit@3 | hit@5 | 놓친 문항 |
|---|---:|---:|---:|---:|---|
| 방향성 행 추가 전, 기존 문항 | 8 | 0.63 | 0.88 | 1.00 | - |
| 방향성 행 추가 후, 기존+방향성 문항 | 16 | 0.44 | 0.63 | 0.88 | TGB-04, TGB-08 |

- 문서가 늘어나자 같은 기존 문항도 순위가 내려갔다. `TGB-04`는 4위에서 5위 밖으로 밀려났다.
- 방향성 문항은 표현이 겹치면 1위로 찾았다(`TGB-05`, `TGB-07`, `SJR-05`). 표현이 다르면 순위가 낮거나 놓쳤다.
  예: `TGB-08` "자정 마감, 다시 없는 가격"은 "구매 경험 약속" 행을 상위 5개 안에서 찾지 못했다.
- 기업 격리 위반은 여전히 0건이다.

**결론: 기업 근거는 순위 상위 몇 개만 고르지 말고 첨부 문서 전체를 판정에 넘겨야 한다.**
이에 따라 기업 검색에 `document_ids`를 주면 순위 없이 첨부 문서의 조각 전부를 파일 순서대로 반환하도록 변경했다.
본문 합계 상한은 30,000자이며 넘으면 `too_large`를 반환한다. 계약은 [RAG 가이드](../rag-mcp/README.md)를 따른다.

## 추가 평가: 허브 조각 원인 수정 후 (2026-10-23)

`RULE-HIST-001`, `RULE-CONTEXT-001`이 무관한 질문에도 상위에 오던 원인은 문서 내용이 아니라 **조각 구성**이었다.

1. **링크 주소 조각:** 본문의 `[기관명](https://...)` 링크가 분할되면서 URL이 대부분인 조각이 생겼다.
   URL 문자열은 어떤 질문과도 비슷하게 계산됐다. → 링크는 표시 문구만 남기고 주소는 빼고 임베딩한다.
   본문 링크 15개의 주소는 모두 해당 문서의 `source_urls`에 이미 있어 출처 정보는 줄지 않는다.
2. **짧은 끝 조각:** 96토큰 고정 간격으로 자르면 마지막에 출처 이름만 남은 짧은 조각이 생겼다
   (예: "한다. 근거: 국립5·18민주묘지, 민주화운동기념사업회, 국가기록원."). → 같은 크기로 고르게 나눈다.

전체 결과: [retrieval-tuning.json](eval/retrieval-tuning.json). 문항·모델·top_k는 직전 평가와 같다.

| 지표 | 수정 전 | 수정 후 |
|---|---:|---:|
| 사회 hit@1 / hit@5 / MRR | 0.53 / 0.93 / 0.69 | **0.80** / 0.93 / **0.87** |
| 전체 hit@1 / hit@5 / MRR | 0.45 / 0.90 / 0.63 | **0.58** / 0.90 / **0.71** |
| 무관 문구 1위 점수 평균 / 최대 | 0.42 / 0.50 | **0.29 / 0.32** |
| 정답 점수 평균 | 0.47 | 0.47 |
| 두 문서가 사회 질문 상위 2개에 나온 횟수 | 19 | 7 |
| 기업 격리 위반 | 0 | 0 |

- 순위가 오른 문항: `SOC-02` 5→2, `SOC-05` 3→1, `SOC-12` 3→1, `SOC-10` 2→1, `SOC-04` 2→1, `SCOPE-01` 2→1
- 내려간 문항: `SOC-11` 1→2
- 무관 문구의 1위 점수가 정답 점수 평균보다 낮아졌다. 다만 정답 점수의 최솟값(0.10)은 여전히 더 낮으므로
  점수만으로 관련성을 판단하지 않는다는 원칙은 그대로다.
- 기업 문서는 행이 짧아 분할되지 않으므로 결과가 같다. 첨부 문서 검수는 전체 반환이라 순위와 무관하다.
- **`SOC-03`은 여전히 놓친다.** 질문의 "화장품"이 `CASE-HIST-002` 문서에 나오지 않는다.
  같은 내용을 문서 표현("6·25 숫자와 침투를 결합한 화장품 광고")으로 물으면 1위다. 검색 방식이 아닌 문서 표현의 차이다.

## 재실행 방법

평가는 DB의 RAG 문서를 모두 지우고 다시 적재하므로 이름이 `_eval` 또는 `_test`로 끝나는 DB에서만 실행된다.

```bash
docker compose up -d pgvector
docker compose exec pgvector createdb -U adcheck adcheck_rag_eval   # 최초 1회
PYTHONPATH=rag-mcp python -m rag_mcp.evaluation \
  --database-url postgresql://adcheck:adcheck@localhost:5433/adcheck_rag_eval \
  --output docs/eval/retrieval-baseline.json
```

최초 실행 때 모델 파일을 `.cache/embeddings`로 내려받는다. 지연 시간은 실행 장비에 따라 달라진다.
