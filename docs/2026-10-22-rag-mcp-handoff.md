# 2026-10-22 RAG·MCP 작업 및 파트 1 전달 사항

작업 브랜치: `chore/verify-rag-mcp`. 아직 커밋·푸시하지 않은 작업 기록이다.

## 팀 대화에서 확인한 MVP 범위

- 사회·역사 문서는 현재 준비한 묶음을 고정 기준으로 사용한다. 수정·폐기 기능은 이번 범위에서 제외한다.
- 기업 문서는 검수 시 첨부하고 그때 적재한다. 데모는 우리가 만든 합성 CSV/XLSX만 사용한다.
- 같은 기업에 이전에 올린 문서가 있어도 이번 검수에서 선택한 파일만 검색해야 한다.
- 파트 2는 검색 결과를 state에 보존하는 범위까지 맡는다.
- MCP 호출 흐름, 근거 충분성 판단, 최종 판정, 대안 생성, 그래프 분기는 파트 1 담당이다.
- FE HTML은 초안이다. 화면 구조를 참고했으며 키워드 기반 판정 코드는 가져오지 않았다.

## 구현한 내용

1. 기업 검색 REST/MCP에 `document_ids`를 추가했다. 기업 ID와 선택 문서 ID로 먼저 제한한 뒤 top-k를 계산한다.
   기존 호출 호환을 위해 생략/null은 기업 전체 검색이다. 첨부 파일 검수에서는 반드시 목록을 전달해야 한다.
   빈 목록은 오류이고, 없는 문서나 다른 기업 문서로는 검색되지 않는다.
2. Agent 없이 실제 PostgreSQL과 MCP SDK로 업로드·재전송·선택 문서 검색·기업 격리·삭제·실패를 검증하는 테스트를 추가했다.
   HTTP 전송은 테스트 내 ASGI transport를 사용하며, 임베딩은 테스트용이다.
3. 사회·기업 검색 결과 전체를 `social_context_result`, `corporate_value_result`에 저장한다.
   기존 evidence 필드도 유지하며, 상세 근거·출처·점수·검색 상태·메시지가 보존된다.
4. RAG·Business 응답 모델과 Agent 수신 모델에 `related_criteria: list[str]`를 추가했다.
   각 검색 결과 객체 안에서 state에 보존된다. 외부검색은 기존 `external_search_result`를 사용한다.
5. 관련 검수 기준 태그는 아직 생성하지 않는다. 기본값은 빈 목록이다.

## 파트 1에서 연결할 내용

### 첨부 문서 검색

- BE가 업로드 완료 응답에서 받은 `company_id`, `document_id` 목록을 검수 요청에 전달하도록 BE와 계약을 정한다.
- Agent 요청 모델·state·RAG 호출 인자에 선택 문서 목록을 연결한다. 현 Agent 호출 코드는 아직 이 목록을 전달하지 않는다.
- 데모 합성 자료를 검색할 때 `include_synthetic: true`를 전달한다. 샘플의 synthetic 표시를 false로 바꾸지 않는다.
- 파일 없는 검수에서 기업 검색을 생략할지, 필수 첨부로 막을지는 BE·FE·파트 1 합의가 필요하다.

```json
{
  "query": "검수 문구 또는 합의된 검색어",
  "company_id": "seojun_roasters",
  "document_ids": ["seojun_roasters-ethics_policy"],
  "include_synthetic": true
}
```

### 결과·관련 검수 기준 활용

| state 필드 | 내용 |
|---|---|
| `social_context_result` | 사회 검색 전체 결과 또는 미호출 시 null |
| `corporate_value_result` | 기업 검색 전체 결과 또는 미호출 시 null |
| `external_search_result` | 외부검색 전체 결과 또는 미호출 시 null |

- 각 결과에 `related_criteria`가 있다. 예시: `["역사적 사건·상징의 상업적 소비 가능성"]`.
- 위 예시는 FE 표현 참고용이며, 실제 검색에 일괄 삽입한 값이 아니다.
- **제안·미합의:** 파트 1의 판정 단계가 실제로 사용한 근거에 기반해 관련 검수 기준을 작성한다.
  저장할 필드는 준비되어 있지만 태그 생성·최종 FE 응답 노출은 아직 구현하지 않았다.
- `None`(미호출), `empty`(정상 검색·근거 없음), `error`(RAG 호출 실패)를 구분한다.
  외부검색은 기존 timeout/unavailable/error 구분을 유지한다.
- 검색 결과가 있다는 이유만으로 충분한 근거나 위반으로 확정하지 않는다. 상태 판정은 파트 1이 담당한다.
- 최종 ReviewResponse에는 관련 검수 기준과 상세 출처 필드가 아직 없다. BE·FE와 최종 응답을 합의한다.

## 검증 및 남은 범위

- 개발 의존성을 .venv에 설치했다. .env의 값은 변경하지 않았다.
- 실제 pgvector 테스트 DB는 기존 데이터와 분리해 실행·정리한다.
- 실제 임베딩 모델 검색 정확도와 FE→BE→Agent 전체 연결은 이번 테스트로 입증하지 않는다.
- 사회 문서 폐기 처리, 금칙어 로직, LLM 판정·수정안·그래프 분기는 변경하지 않았다.
- 현재 변경 기준: 전용 pgvector DB를 포함한 전체 테스트 **93개 통과**.
- 전체 Ruff lint 통과, 변경한 Python 파일 및 RAG 영역의 format 검사 통과, `git diff --check` 통과.
- 검색 결과·관련 검수 기준의 adapter/state 보존, 정상 빈 결과·오류 구분, MCP 응답 필드를 검증했다.
- 검사에 사용한 테스트 임베딩과 합성 응답은 실제 모델의 검색 정확도·태그 생성 품질을 검증하지 않는다.
